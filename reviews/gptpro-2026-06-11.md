The same public file view shows the background runner re-entering bash -c and interpolating these variables directly into the command string. 
GitHub

Scenario

Any argument that contains a single quote breaks out of the intended assignment in the child shell.

Example:

Bash
./run_optimization.sh --targets "x'; touch /tmp/pwned; #" 

The generated child script contains:

Bash
TARGETS='x'; touch /tmp/pwned; #'

That executes before run_optimization even starts. The same class applies to ALGORITHM, MODEL, CV_FOLDS, DROPOUT, OUTPUT_DIR, DATASETS_DIR, and paths like PROJECT_DIR or SCRIPT_DIR if the repository is located in a directory containing a quote.

Fix

Do not serialize shell source code with interpolated values. Re-exec the script in foreground mode with an argv array:

Bash
if [[ "$FOREGROUND" == "true" ]]; then
    run_optimization 2>&1 | tee "$OUTPUT_DIR/optimization.log"
else
    bg_cmd=(
        "$0"
        --foreground
        --targets "$TARGETS"
        --algorithm "$ALGORITHM"
        --model "$MODEL"
        --cv-folds "$CV_FOLDS"
        --dropout "$DROPOUT"
        --output-dir "$OUTPUT_DIR"
        --datasets-dir "$DATASETS_DIR"
    )
    nohup "${bg_cmd[@]}" > "$OUTPUT_DIR/optimization.log" 2>&1 &
fi

Also validate enums and names before launching:

Bash
[[ "$ALGORITHM" =~ ^(bootstrap|copro|iterative)$ ]] || exit 2
[[ "$MODEL" =~ ^(haiku|sonnet|opus)$ ]] || exit 2
[[ "$TARGETS" =~ ^[A-Za-z0-9_,.-]+$ ]] || exit 2

For target names specifically, I would reject /, .., whitespace, quotes, control characters, and leading -.

Command-injection-specific notes

claude_runner.py does not have classic shell injection from prompt text: it uses subprocess.run(cmd, ...) with cmd as a list, and it includes -- before full_prompt. That part is good.

The P0 command injection is specifically in run_optimization.sh background mode, where safe arrays are abandoned and shell source is assembled as a string. Foreground mode is much safer because it uses arrays:

Bash
local cmd=(python3 "$SCRIPT_DIR/batch_optimize.py")
cmd+=(--model "$MODEL")
...
if "${cmd[@]}"; then

The foreground command still needs validation and safe logging, but it is not the same class of shell injection.

Three likely-missed findings to check next

Downstream optimizer loops in batch_optimize.py, bootstrap.py, copro.py, and iterative.py: this review only saw the shell runner and CLI wrapper. The real call multiplicity, cost amplification, and prompt-output logging likely live there.

Symlink attacks: even after name validation, ~/.claude/agents/<name>.md or backup paths could be symlinks. Deployment should reject symlinks or open files with safe flags and containment checks on resolved paths.

Training dataset poisoning path: if JSONL datasets can be supplied by a repo or PR, they likely influence prompts, demos, scores, and deployed prompt text. That path needs a full taint trace from dataset row → Claude prompt → model output → metric extraction → OptimizedPrompt → deployment.
